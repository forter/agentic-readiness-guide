# מודול 3 - להיות אמינים ★
*"סוכנים והשירות שלכם יכולים לאמת זה את זה הדדית לפני שהם מחליפים ערך."*

## שאלת הסוכן
> _"יש לי את כוונת המשתמש ואת אישורי הגישה לפעול בשמו. כיצד אנחנו מוכיחים זהות זה לזה לפני שכסף, נתונים או מוצרים נעים?"_

מודולים 1 ו-2 הם לקריאה-בלבד. מודול 3 הוא המקום שבו קריאות הופכות לכתיבות. כל פרוטוקול כאן מגיע עם מפרט שבונים מולו; העבודה היא בחירת ספריות טובות, תזמון האינטגרציות, ואחסון כמה נקודות קצה מסוג well-known.

## מודל האיומים, בקצרה

ללא זהות, ארבעה דברים צפויים קורים: **בוטים זדוניים מתחזים לטובים** (RFC 9421 מסיים את הניחושים); **מפתחות API דולפים ונשלחים מחדש** (טוקנים קצרי-חיים עם רוטציה מתחמים את רדיוס הנזק); **סוכנים סוטים** תחת prompt injection (הרשאות לכל-משאב תוחמות כל קריאה בודדת); ו**סביבות sandbox בשכבה החינמית נשאבות** (קווי-בסיס התנהגותיים בהנפקה סוגרים על כך). כל הארבעה ניתנים לפתרון עם הסטנדרטים שב-[3.1](./m3-1-oauth-discovery.md)-[3.3](./m3-3-self-serve-credentials.md).
