# 模块1 - 可被发现
*“无需任何人告知去哪里找，智能体就能定位到你的产品。”*

## 智能体的问题
> _“一位顾客让我找一双防水越野跑鞋，10 码，120 美元以内。哪些网站有货？”_

## 漏斗已经在移动

在每一场行业活动和大多数分析师简报中，你都会听到这样的反对意见：智能体驱动的*交易*量仍然很小。这在今天是事实 - 但它忽略了已经在发生的事情。眼下正被颠覆的环节是搜索与发现。智能体正在对你的网站形成看法，读取或读不到你的商品目录，并在任何交易被提上桌面之前很久，就已经在塑造用户的购买意向。

这些阶段并不相互独立。如果智能体在发现阶段就读不懂你，你在交易阶段就根本不在候选之列 - 流程压根走不到那一步。因此，那些要等智能体流量变得“可观”才行动的网站会发现流量早已转移：智能体更早就建好了自己的候选清单，来源是当时恰好可读的那些网站，而不在清单上的网站永远不会被重新考虑。无论你经营的是电商商店、SaaS 平台还是交易市场，这一点都成立 - 发现是横在所有这些业务前面的那道门。

可发现性是五个模块中成本最低的一个，而且低得多。大部分工作是放在源站根目录或 `/.well-known/` 下的静态文件 - 写一次就可以忘掉的文本和 JSON。

## 三个发现视角

智能体通过三个并行的界面触达你，每个界面有自己的文件：**传统搜索**（Googlebot、Bingbot）、**AI 训练爬虫**（GPTBot、CCBot - 你可以允许，也可以限制），以及**实时智能体爬虫**（ChatGPT-User、ClaudeBot、Perplexity-User - 它们在用户提问的那一刻抓取你的网站）。对“敲门者究竟是谁”的密码学验证见 [3.2](./m3-2-web-bot-auth.md)；工具发现类注册目录的登记见 [4.6](./m4-6-agent-registries.md)（在 MCP 服务器就绪之后）。
