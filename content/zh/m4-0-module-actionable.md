# 模块4 - 可被执行
*“智能体拥有一份完整的契约，用于调用你的业务逻辑并从错误中恢复。”*

## 智能体的问题
> _“我已通过认证。现在：我能做什么、它长什么样、我搞砸了会怎样、我该如何重试？”_

模块3让智能体证明它是谁。模块4告诉智能体**接下来做什么**。这份契约始于一份 OpenAPI 规范，逐步成长为一个覆盖 MCP、WebMCP、函数调用和 SDK 的、支持流式传输、有速率限制、能感知错误的工具面 - 然后延伸到智能体原生的支付协议和一个对话式 NLWeb 端点。而“我能做什么”横跨整个订单生命周期，不只是发现和结账：智能体流量中有很大一部分发生在购后 - 查订单状态、发起退货、就扣款提出争议 - 这些操作运行在同一套界面上。

## 关于工具调用安全的说明

模块4是工具调用运行**真实业务逻辑**的地方 - 订单、退款、支付。偏离意图的智能体（提示词注入、畸形输入、失控循环）在这里造成的损害最大。三道结构性防线让它可控：按工具划分的 OAuth 权限范围（[3.1](./m3-1-oauth-discovery.md)，在 [4.4](./m4-4-mcp-server.md) 中强制执行）、结构化速率限制与 `Retry-After`（[4.2](./m4-2-rate-limits-and-errors.md)），以及持续的端到端仿真（[5.4](./m5-4-end-to-end-flows.md)）。
